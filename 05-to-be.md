# 5. Описание выбранной концепции и модель процессов TO-BE

Для реализации концепции выбран **Вариант C**: доработка существующей СДО Moodle собственным плагином поверх штатной подсистемы Competencies. Поскольку данные об оценках уже находятся в Moodle, внешняя интеграция не требуется. Тяжёлые расчёты показателей освоения выполняются фоновым процессом по расписанию, что позволяет выдержать пиковую нагрузку в 300 пользователей во время сессии.

## 5.1. Описание целевого процесса (TO-BE)

После внедрения системы процесс мониторинга компетенций выстраивается следующим образом:
1. **РОП** в начале учебного периода формирует или актуализирует карту компетенций, устанавливает пороги и правила интерпретации. Плагин автоматически сохраняет новую версию карты и журнал действий.
2. **Преподаватель** в своих курсах Moodle размечает учебные активности и элементы оценивания, связывая их с компетенциями. В процессе обучения преподаватель выставляет оценки непосредственно в Moodle.
3. **Система (Moodle)** по расписанию получает данные об оценках, рассчитывает показатели освоения компетенций по единым правилам и весам, заданным РОПом.
4. **Система** проверяет соблюдение порогов. Если порог нарушен, плагин автоматически формирует предупреждение и отправляет его через штатные сообщения Moodle студенту и РОПу.
5. **Студент** в любой момент может просмотреть свой актуальный прогресс по компетенциям и полученные сообщения в личном кабинете. При необходимости студент обращается за помощью к преподавателю.
6. **РОП** анализирует автоматически сформированные отчёты (по студентам, программе, сравнение когорт), выявленные риски и принимает решения (например, корректирует карту или инициирует поддержку отстающих).

## 5.3. Границы системы

| Действие | Статус в TO-BE | Исполнитель / Инструмент |
| --- | --- | --- |
| Формирование и актуализация карты компетенций, установка порогов | **Ручное** (инициирующее) | РОП |
| Разметка учебных активностей и элементов оценивания в курсах | **Ручное** | Преподаватель (в Moodle) |
| Выставление оценок за учебные активности | **Ручное** (внешнее) | Преподаватель (в Moodle) |
| Сохранение версии карты и запись в журнал действий | **Автоматическое** | Плагин мониторинга |
| Расчёт показателей освоения компетенций (по весам и правилам) | **Автоматическое** | Фоновый процесс плагина |
| Проверка порогов и формирование предупреждений | **Автоматическое** | Плагин мониторинга |
| Отправка сообщений об отставании | **Автоматическое** | Штатная система сообщений Moodle |
| Формирование отчётов по студентам, когортам и программе | **Автоматическое** | Плагин мониторинга |
| Анализ отчётов и принятие управленческих решений | **Ручное** | РОП |
| Оказание методической поддержки отстающим студентам | **Ручное** | Преподаватель |

## 5.4. Устранение проблем текущего процесса (AS-IS)

| № | Проблема AS-IS | Решение в модели TO-BE |
|---|---|---|
| 1 | **Ручной труд и ошибки:** Сопоставление оценок с компетенциями вручную в Excel. | Оценки берутся из Moodle напрямую, расчёт компетенций автоматизирован плагином по единым правилам. |
| 2 | **Запоздалая реакция:** РОП узнаёт о проблемах только после сессии. | Фоновый расчёт и мгновенные уведомления студенту и РОПу при нарушении порога в реальном времени. |
| 3 | **Отсутствие прозрачности для студентов:** Студенты не видят свои компетенции. | Студент видит дашборд прогресса в своём профиле Moodle с привязкой к дисциплинам. |
| 4 | **Разрозненность данных и риски ИБ:** Файлы на личных ПК, нет контроля доступа. | Все данные хранятся в единой защищённой СУБД Moodle на серверах в РФ, доступ строго по ролям. |
| 5 | **Отсутствие единой аналитической картины:** Нет сводки для РОП. | РОП использует встроенный дашборд плагина для сводки по группам и сравнения когорт в один клик. |
| 6 | **Потеря истории при смене плана:** Старые карты теряются. | Плагин автоматически создаёт и хранит версии карт компетенций и журнал всех изменений. |

## 5.5. Ключевые особенности целевого процесса

1. Компетенции размечаются в курсах Moodle самими преподавателями.
2. Оценки берутся из Moodle напрямую, без отдельного импорта и выгрузок.
3. Расчёты, проверка порогов, уведомления, версии карты и отчёты выполняет собственный плагин.
4. Уведомления отправляются через штатные сообщения Moodle.
5. РОП анализирует отчёты и принимает управленческие решения на основе данных.
6. Преподаватели оказывают поддержку студентам при выявлении рисков отставания.
7. Все данные хранятся в Moodle на серверах в РФ, доступ осуществляется по ролям.
